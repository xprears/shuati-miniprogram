# 用 AI 生成标准题库 JSON

不想写解析脚本？把题库文档直接丢给大模型，用下面两段提示词即可产出标准 `questions.json` 与解析文件。
配合 `python3 build/build_bank.py` 就能编译成 App 能读的产物。

**整体流程**

```
题库原文（PDF / Word）──AI 提示词 A──▶ build/questions.json
                                        │
        解析（可选）──AI 提示词 B──▶ build/explanations/ch1_analysis.json
                                        │
                        python3 build/build_bank.py ──▶ miniprogram/utils/qbank.js
```

把文档交给 AI：支持读文件的模型可直接上传 PDF / Word；不方便上传时，在文档里全选复制文本粘贴也可以。

---

## 提示词 A：题库原文 → questions.json

> 复制下面整段给 AI，然后跟上你的题库原文。

```
你是题库结构化助手。我会给你一份题库文档的原文（PDF 提取文本或 Word 复制文本）。
请把它转成标准题库 JSON：只输出 JSON，不要解释文字，不要 Markdown 代码块标记。

一、输出结构
一个 JSON 数组，每个元素一道题，字段如下：
- id：字符串，从 "q0001" 开始连续编号、补足 4 位（q0001、q0002、…）
- type：只能是这七个值之一
    judge 判断题 / single 单选题 / multi 多选题 /
    essay 论述题 / scenario 情景判断题 / case 案例分析题 / operation 实操模拟题
- stem：题干，去掉题号与答案标注
- options：客观题必填，格式 [{"key":"A","text":"选项文字"}, …]，key 从 A 起连续、不许跳号
    判断题固定为 [{"key":"A","text":"正确"},{"key":"B","text":"错误"}]
- answer：客观题必填。判断题写 "√" 或 "×"；单选题一个字母如 "A"；多选题两个以上字母如 "ACD"
- reference：主观题必填，参考要点原文（保留 (1)(2)(3) 编号与换行，写成 \n）
- part：大部标题原文，取文档里「一、」「二、」这类行的内容
- chapter：章节标题原文，形如「第一章 判断题【208题】」
- category：分类标签，取「第N类 xxx【M题】」中的 xxx，没有就写 null
- qno：题目在原文中的题号（整数）

二、内容规则
1. 空位统一写成「（ ）」——全角左括号 + 一个空格 + 全角右括号。
   原文形如「在（B）米及以上」「…属于（C）」时，答案字母被印在空位里，
   一律换成「（ ）」，绝不要把字母留在题干里，也不要留成「在米及以上」。
2. 判断题题干不带答案标记，选项固定 A 正确 / B 错误。
3. 选项文字去掉前导的「A.」「A、」标记和多余空白。
4. 主观题（essay / scenario / case / operation）没有 options 和 answer，只有 reference。
5. 原文的错别字、重复题照原样保留，不要替我修改题干。

三、输出前自检
- id 唯一且连续；题目总数与原文一致
- 每个客观题 options 的 key 从 A 连续，answer 里的字母都能在 options 中找到
- 多选题 answer 至少 2 个字母
- JSON 合法：无尾逗号、无注释、字符串用双引号

四、分批
原文超过 150 道题时，分批给我完整 JSON 数组，并保证 id 与原文顺序连续；
我会说「继续」，你就输出下一批。
------------------------------------------------------------------
下面是题库原文：
（在此粘贴原文）
```

## 提示词 B：题库 → 解析（可选）

> 复制下面整段给 AI，再附上已经生成好的 `questions.json`。

```
你是考试题库解析作者。我会给你一个题库 JSON（字段：id / type / stem / options / answer / reference）。
请为每道题写解析，输出「题号 → 解析」的 JSON 对象，只输出 JSON，不要其他文字。

写作要求：
1. 客观题（single / multi）：首句直接给结论，并把正确选项的核心文字并列写出来；
   干扰项只能出现在第一个句号之后，不要用「A 为…」「B 为…」这种字母开头。
2. 判断题（judge）：固定以「正确。」或「错误。」开头，随后说明理由。
3. 多选题：首句并列所有正确项；若选项全对，写「本题各项均正确，无干扰项」。
4. 主观题（essay / scenario / case / operation）：不少于 120 字，逐条覆盖 reference 里的
   每个要点编号，给出机理、单位或取值依据，不能只复述题干。
5. 不要编造题干与选项之外的事实性内容（数值、倍率、标准号）。若题库答案与学科常识冲突，
   以题库答案为准，并在解析末尾用括号注明严格定义；不要替题库编一套自相矛盾的机理。
6. 挖空原文型的题可以写「出处 + 原文 + 逐项说明干扰项为何不选」，
   但不要把干扰项说成「也是错误做法」。
7. 每道题解析不少于 30 字；不同题的解析不要逐字重复。

输出格式：{"q0001": "解析文字", "q0002": "解析文字", …}
键必须是题库里的 id，一个都不能少。
------------------------------------------------------------------
下面是题库 JSON：
（在此粘贴 questions.json）
```

## 示例：输入 → 输出

**输入（原文片段）**

```
第二章 单选题【3题】
1、下列设备中，工作在数据链路层的是（A）
A. 交换机  B. 路由器  C. 中继器  D. 集线器
```

**输出（AI 应产出）**

```json
[
  {
    "id": "q0001",
    "type": "single",
    "stem": "下列设备中，工作在数据链路层的是（ ）",
    "options": [
      { "key": "A", "text": "交换机" },
      { "key": "B", "text": "路由器" },
      { "key": "C", "text": "中继器" },
      { "key": "D", "text": "集线器" }
    ],
    "answer": "A",
    "part": "一、通用题【示例】",
    "chapter": "第二章 单选题【3题】",
    "category": "通信基础",
    "qno": 1
  }
]
```

注意两点：题干里的 `（A）` 被换成了 `（ ）`；选项文字去掉了 `A.` 前缀。

## 拿到结果之后

1. 题库存成 `build/questions.json`（**根节点是数组**）。
2. 解析存成 `build/explanations/ch1_analysis.json`、`ch2_analysis.json`…（文件名必须是 `ch<数字>_analysis.json`）。
3. 构建并查看结果：

```bash
python3 build/build_bank.py
```

脚本会校验 id 是否重复、题型是否合法、选项键是否连续、答案是否越界，并报告解析覆盖到多少题。
有报错就把它连同你的 JSON 片段丢回给 AI 修正。

> 用 AI 生成后建议抽查 10–20 题：题干有没有被改写、答案字母有没有抄串、空位有没有还原成「（ ）」。
> 这些是最容易出错的地方。
