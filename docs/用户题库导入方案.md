# 用户题库导入方案（空壳发布版）

> 2026-10-16 定稿。目标：小程序**发布物不含任何题库与解析**，由终端用户自行导入。
> 本文回答四个问题：①上传入口 ②可刷题的格式 ③使用引导 ④文件如何进小程序，并给出实施计划。

---

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| ① 上传入口 | 新增主包页面 `pages/import/import`（非 tab 页）。三个常驻入口：**首页空态大按钮**（无题库时）、**分类页「题库管理」条**（有题库时，用于替换/导出/清除）、**设置页缺题库时的兜底按钮** |
| ② 格式 | **只认标准题库 JSON**（与 `docs/ai-bank-prompt.md` 提示词 A 产出一致）。自动识别两种形态：详细态（`id/type/stem/…`）和紧凑态（`i/t/s/…`，即 qbank.js 内容，粘贴整个文件自动剥离 `module.exports`）。校验规则从 `build_bank.js` 原样移植 |
| ③ 引导 | App 内置**一键复制的 AI 提示词** + **8 题型模板 JSON** + 导入三步引导 + 带题号的错误反馈（最多列 10 条）。零外部链接依赖（个人主体禁 web-view） |
| ④ 上传机制 | **主路径：复制粘贴 JSON 文本**（全场景可用，无 API 限制）。**辅路径：`wx.chooseMessageFile` 从微信聊天会话选文件**（需从聊天卡片进入小程序 + 隐私指引声明）。web-view、本地文件管理器、相册、云开发均不采用 |

## 1. 架构改造：题库从「构建期内置」改为「运行期导入」

### 1.1 数据流对比

```
【现状】
build/questions.json ──build_bank.js──▶ miniprogram/utils/qbank.js ──require──▶ logic.js ──▶ 各页面
                                        （题库烧进发布包，2MB 主包的最大头）

【改后】
发布物：无 qbank.js

用户设备：
  AI 生成的题库 JSON ──┐
                       ├─▶ pages/import/import（粘贴/选文件 → 规范化 → 校验）
  微信聊天会话里的文件 ──┘        │
                                ▼
                    utils/bank-store.js（分片存 wx.storage）
                                │  logic.reload()
                                ▼
                    utils/logic.js（QLIST/QMAP/TREE 运行期重建）──▶ 各页面
```

Node 测试 / 开发预览兜底：`bank-store` 在无 `wx` 环境（Node）下自动回退读
`miniprogram/utils/qbank.js`（存在则用，不存在返回空数组）——`mp-logic-test` 等脚本行为不变，
开发时 `node build/build_bank.js --sample` 生成的示例题库仍可直接喂给测试。

### 1.2 文件改动清单

| 文件 | 动作 | 说明 |
|---|---|---|
| `miniprogram/utils/bank-validate.js` | **新增** | `normalize(raw)` / `validate(qs)` / `compact(qs)` / `TEMPLATE` 常量。从 `build_bank.js` 抽出，**Node 与小程序双端复用同一实现**，`build_bank.js` 改为 require 它 |
| `miniprogram/utils/bank-store.js` | **新增** | 存储层：`load()` / `save(verbose[])` / `clear()` / `info()`。wx.storage 分片（单 key ≤ 1MB 硬限），`bank.meta` + `bank.0…N` |

### 1.3 logic.js reload 机制（关键设计）

```js
// logic.js 骨架
var bankStore = require('./bank-store.js');
var QLIST = [], QMAP = {}, TREE = [];
var api = { /* 原有导出 */ };
function build(bank) { /* 重建 QLIST/QMAP/TREE，并 api.QLIST = QLIST … */ }
api.reload = function (bank) { build(bank || bankStore.load()); };
module.exports = api;
build(bankStore.load());   // require 时首次构建
```

- 页面全部通过 `onShow` 读 `logic.QLIST/TREE`，**不存在模块加载期缓存**（已核对 index/bank/setup/store 均如此），属性原地替换即可生效。
- 导入页保存成功后：`bankStore.save(qs)` → `logic.reload()` → `navigateBack`，首页 `onShow` 自然刷新。

### 1.4 存储分片（单 key 1MB / 总量 10MB 硬限）

- `bank.meta`：`{ count, size, chunks, at, types }`（size 为 UTF-8 估算，`unescape(encodeURIComponent(s)).length` 经典算法，小程序无 Buffer/TextEncoder 可用）。
- `bank.0 … bank.N`：紧凑 JSON 串按 **700KB（UTF-8）** 切片，读时拼接 `JSON.parse`。
- 上限：总量 **9MB**（约 1.2 万题带解析）。超限拒绝并提示删解析/分批。
- 紧凑态比详细态省约 45%（去掉重复字段名），3238 题全解析约 2.5MB → 4 片，实测无感。

### 1.5 主包体积预算

当前 1.73MB。删除 `qbank.js`（−7.6KB）＋ 新增导入页约 30KB ＋ 模板/提示词常量约 8KB → **约 1.76MB**，余量仍 > 200KB。

## 2. 问题 1：上传入口

| 入口 | 出现条件 | 去向 |
|---|---|---|
| 首页 hero 空态大按钮「导入题库」 | `logic.QLIST.length === 0` | `/pages/import/import` |
| 分类页顶部「题库管理」条 | 恒显示（有题库时显示 N 题/导入时间，无题库时显示「还没有题库」） | `/pages/import/import` |

设计取舍：
- 空态只有**一个**导入入口（2026-10-18 合并）：原「导入指南」次按钮指向同一页面、差别仅是页尾多一块与步骤卡重复的说明，已删除；导入流程本身由页内 1/2/3 步骤卡承担。
- 不放 tabBar（4 个 tab 已占满，导入是低频任务页）；**不放 hero 长按**（原为反馈汇总入口，反馈功能已于 2026-10-16 移除，该手势保持闲置）。
- 模式卡在无题库时不隐藏、置灰点击 → toast「请先导入题库」，比整块隐藏更利于理解产品形态。

## 3. 问题 2：上传什么格式才能刷题

### 3.1 唯一格式：标准题库 JSON

**详细态**（提示词 A 直接产出，推荐，用户零转换）：

```json
[
  {
    "id": "q0001",
    "type": "single",
    "stem": "下列设备中，工作在数据链路层的是（ ）",
    "options": [{ "key": "A", "text": "交换机" }, { "key": "B", "text": "路由器" }],
    "answer": "A",
    "part": "一、通用题",
    "chapter": "第二章 单选题",
    "category": "通信基础",
    "analysis": "交换机工作在数据链路层……"
  }
]
```

**紧凑态**（`i/t/s/p/c/g/o/a/r/x`，即 `qbank.js` 的数组内容）：`normalize()` 自动识别；用户若把整个 `qbank.js` 文件内容粘进来，自动剥离注释头与 `module.exports = … ;`。

字段规则（与构建期完全一致，勿另立标准）：

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✓ | 全局唯一 |
| `type` | ✓ | `judge/single/multi/essay/scenario/case/operation` 七选一 |
| `stem` | ✓ | 题干；空位一律全角「（ ）」 |
| `options` | 客观题 ✓ | `[{key,text}]`，key 从 A 起连续，选项数不固定（3/5 项均合法） |
| `answer` | 客观题 ✓ | 判断 `√`/`×`；单选单个字母；多选 2 个以上字母 |
| `reference` | 主观题 ✓ | 答案要点（无则 App 显示空，仅 warn） |
| `part` / `chapter` | ✓ | 大部 / 章节（树结构与筛选依赖） |
| `category` | ✗ | 专业题分类，可空 |
| `analysis` | ✗ | 解析，无则不显示解析区 |

### 3.2 校验（移植自 `build_bank.js`，导入时实时跑）

error：id 重复 / 必填字段缺失 / type 非法 / 选项键断号 / 空选项文本 / 判断答案非 √× / 单选非单字母 / 多选不足 2 字母 / 答案含不存在选项。
warn：主观题无 reference。
导入页把 error **按题号列出前 10 条**，并附常见原因（尾逗号、单引号、中文引号、从 Word 直接复制带格式）。

### 3.3 明确不做（及原因）

| 候选格式 | 不做的原因 |
|---|---|
| CSV / Excel | 解析库 SheetJS 约 1MB，主包放不下；丢字段/串列后错误定位困难 |
| PDF / Word | 自动解析链已整体删除（见项目记忆），且 PDF 版式陷阱多；**正确做法是让 AI 转 JSON**——这正是 App 内嵌提示词的价值 |
| 自定义 DSL / 纯文本 | 解析规则脆弱，用户学习成本高 |
| 云开发网盘 | 用户要自建云环境、有费用、有账号门槛，与「零门槛工具」定位冲突 |

## 4. 问题 3：如何引导用户使用

导入页即引导主页，三段式：

```
① 获取题库 JSON
   [一键复制 AI 提示词]  [查看 8 题型模板]
   文案：把提示词发给任意 AI（如元宝/DeepSeek/豆包），附上你的题库文档，
         AI 会返回一份标准 JSON。也可直接粘贴你已有的 JSON 文件内容。

② 导入
   [大文本粘贴框]  或  [从微信聊天记录选择文件]
   提示：大题库（>2000 题）建议用聊天文件导入，避免输入法截断。

③ 校验并启用
   成功：N 题 · 题型分布 · 体积 · 解析覆盖 x/y    [启用题库]
   失败：✗ 第 12 题 缺必填字段 answer …（前 10 条）
```

其他引导细节：
- **提示词常量**：`docs/ai-bank-prompt.md` 提示词 A 的浓缩版（约 3KB）硬编码进导入页，`wx.setClipboardData` 一键复制。不依赖任何外链。
- **模板常量**：从 `build/sample/questions.sample.json` 提取 7 个题型各 1 题，既是格式说明也是最小可用题库（粘贴即跑通全流程）。
- **导入成功后**：toast「已导入 N 题」→ 自动返回首页，hero 显示正常统计；换库时按题库指纹询问是否清空旧记录。
- **导出/备份**：导入页底部「导出到剪贴板」（紧凑 JSON 全文）——换手机/备份用，也倒逼格式透明。
- **清除题库**：二次确认 modal，清 storage 分片 + reload 空态。

## 5. 问题 4：文件如何上传到小程序

### 5.1 可行机制矩阵（2026-10 微信官方口径核实）

| 机制 | 可行性 | 说明 |
|---|---|---|
| **剪贴板粘贴 JSON 文本** | ✅ 主路径 | 无场景限制、无主体限制、无隐私声明门槛；用户从任何地方（AI 对话、备忘录、文件 App）复制文本粘进 textarea |
| **`wx.chooseMessageFile` 会话选文件** | ✅ 辅路径 | 只能选**微信聊天会话**（文件传输助手/群聊/单聊）里出现过的文件，**不能读手机本地文件系统**；返回 `tempFiles[].path`，`wx.getFileSystemManager().readFile({encoding:'utf8'})` 读文本 |
| web-view 嵌 H5 上传页 | ❌ | 个人主体禁配业务域名，官方明确「个人类型小程序暂不支持」 |
| `wx.chooseImage` 相册选图 | ❌ | 只能选图片，题库 JSON 走不了 |
| 本地文件管理器直读 | ❌ | 小程序无此能力 |
| 微信云开发存储 | ❌ 不采用 | 用户需自建云环境/费用/账号；与零门槛定位冲突 |

### 5.2 主路径：粘贴（默认引导）

- textarea **不绑定 value**（几 MB 文本 setData 会卡死渲染），`bindinput` 只存 `this.raw`，点「校验」才解析。
- 输入预处理（`normalize`）：剥 ```` ```json … ``` ```` 围栏 → 剥 `module.exports =` 与尾 `;` → 去首尾空白 → `JSON.parse` → 识别详细/紧凑态。
- iOS 用户用系统「粘贴」菜单长按 textarea 完成，**不调 `wx.getClipboardData`**，无读取剪贴板的隐私声明负担。

### 5.3 辅路径：聊天会话文件

```js
wx.chooseMessageFile({ count: 1, type: 'file',
  success: (res) => {
    const f = res.tempFiles[0];
    if (f.size > 5 * 1024 * 1024) return wx.showToast({ title: '文件超过 5MB', icon: 'none' });
    wx.getFileSystemManager().readFile({
      filePath: f.path, encoding: 'utf8',
      success: (r) => this.tryImport(r.data)   // 与粘贴共用同一套 normalize+validate
    });
  }
});
```

- 用户操作路径：把 `题库.json` 发给自己（文件传输助手）→ 从小程序卡片进入 → 导入页点「从聊天记录选择」。
- **限制写进 UI ：非会话场景进入小程序时该按钮点击后直接 fail，fail 回调里 toast 引导「请从微信聊天里打开小程序，或改用粘贴」。
- **发布前必须**：公众平台 → 用户隐私保护指引 → 声明「从聊天会话中选择文件」用途，否则调用被静默拦截。剪贴板写入（复制提示词/模板/导出）一并勾选。

### 5.4 隐私与发布勾选清单

1. 用户隐私保护指引：`wx.chooseMessageFile`（聊天会话文件）+ `wx.setClipboardData`（剪贴板）。
2. 类目维持「工具 → 信息查询」，文案继续避开敏词。
3. `node build/mp-lint.js --release` 全绿（含「发布物无 qbank.js」检查）后才出预览/发布。

### 已识别风险与对策

| 风险 | 对策 |
|---|---|
| 大题库（数千题长解析）JSON.parse + 建索引在低端机慢 | 导入时 `showLoading`；compact 存储；>2000 题引导走文件路径 |
| Android 输入法粘贴超大文本截断 | 粘贴框旁明示「大题库建议用聊天文件」；readFile 路径天然无此问题 |
| 换题库后旧答题记录错位 | 记录按 qid 匹配，不匹配的自然不显示；替换前 modal 明示，不做静默删除 |
| 隐私声明漏配导致 chooseMessageFile 静默失败 | 发布清单第 1 条；fail 回调兜底引导粘贴 |

## 7. 附：8 题型最小模板（导入页内置常量的内容来源）

从 `build/sample/questions.sample.json` 每题型取 1 题生成，字段形态即第 3.1 节表格的完整示例：judge（`√`）+ single（3 项）+ multi（5 项）+ essay/`reference` + scenario + case + operation。粘贴即可跑通「导入 → 顺序练习 → 判分 → 报告」全链路。
